# Политика безопасности

## Куда сообщать об уязвимостях

Не публикуйте уязвимости в открытых issue. Сообщите через **GitHub Security Advisories** репозитория (вкладка Security → Report a vulnerability) или приватным сообщением владельцу репозитория.

Мы постараемся ответить в течение 7 дней и согласовать срок раскрытия.

## Область

Проект — сборщик публичных списков маршрутизации. У него **нет** доступа к роутеру, VPN-серверу или какой-либо инфраструктуре пользователя. Сборка работает только с публичными источниками и GitHub API.

В область относятся:

- компрометация или подмена данных источников;
- уязвимости в сборщике, публикаторе, мониторинге и workflow (включая права токенов);
- нарушение целостности артефактов (SRS, SHA-256, манифест).

## Модель угроз и меры

- **Источники**: только HTTPS, ограничение размера, SHA-256 кеша, offline-replay по проверенному кешу, условные GET с ETag. Откат на предыдущий проверенный набор при сбое обязательного источника.
- **Публикация**: через черновик, повторное скачивание и проверка каждого вложения, откат черновика при сбое. Теги удаляются только с префиксом проекта.
- **CI**: экшены закреплены по SHA, минимальные права токенов, CodeQL, Bandit, Dependabot. Зависимости — с хешами (`--require-hashes`).
- **Проверки**: компиляция и обратное чтение SRS, `sing-box check`, semantic diff, обязательные probes, output-схемы.

## Компрометация источника

Если источник начал отдавать вредоносные или ошибочные данные:

1. Сборка остановится на drift-ограничениях (доля роста/падения) или обязательных probes.
2. Текущий опубликованный релиз остаётся нетронутым — наборы не перезаписываются.
3. Источник удаляется или помечается в `config/sources.json`, после чего запускается ручная сборка с пересмотром baseline.

## Уязвимости в данных

Если в опубликованный набор попали неверные записи (ложное включение или потеря покрытия), откройте обычный issue по форме «Ресурс идёт не по тому маршруту». Это не требует приватного канала.
