# Сборка и сопровождение

[← README](../README.md)

Для использования готового списка достаточно ссылки из README. Эта страница описывает проверку релизов, локальную сборку и обслуживание собственного форка.

## Как формируется набор

Источники и пределы их размеров заданы в [sources.json](../config/sources.json). Каждый обязательный источник скачивается по HTTPS; URL, время получения и SHA-256 записываются в manifest.

Домены нормализуются через IDNA2008/UTS46. Точные `domain` остаются точными; `domain_suffix` охватывают сам домен и его поддомены. Политика фильтрует общие зоны и платформы до объединения. Удаление общей записи, например `googleapis.com`, сохраняет явно перечисленные дочерние домены.

Public Suffix List используется для фильтрации широких правил. Отдельные домены сервисов из секции PRIVATE сохраняются, если явно перечислены в `service_owned_suffixes` и присутствуют в источниках. Сам по себе этот параметр домены не добавляет. PRIVATE wildcard не используется для удаления доменов отдельных арендаторов.

После объединения удаляются только дубли и условия, покрытые уже существующим суффиксом. Новые родительские домены не создаются. Файл [probes.json](../config/probes.json) содержит примеры для отчёта; он не задаёт маршруты или исключения.

Известные ограничения источников: `unavailable-in-russia` пополняется накопительно и не гарантирует своевременное удаление записей; `habr.com` на момент первоначальной сборки присутствовал в нескольких источниках и попадал в VPN-набор. Причину совпадения следует проверять по отчёту конкретного релиза. Списки и зависимости сопровождаются их авторами; ссылки на исходные проекты приведены в README.

## Проверка релиза

В [Releases](https://github.com/Vanilla-SilQ-HD/Routing/releases) публикуются:

| Файл | Назначение |
| --- | --- |
| `blocked-domains.srs` | Бинарный набор для sing-box |
| `blocked-domains.srs.sha256` | SHA-256 бинарного файла |
| `blocked-domains.json.gz` | Сжатый исходник набора |
| `manifest.json` | Источники, хеши, размеры и результаты проверок |
| `report.html`, `probes.json`, `excluded.json` | Отчёт, примеры совпадений и исключённые широкие записи |
| `release.json`, `SHA256SUMS` | Идентификатор сборки и хеши опубликованных вложений |

Для проверки пары «файл + хеш» сначала фиксируйте тег релиза: между двумя обращениями к `latest` может выйти новая версия.

```powershell
$release = Invoke-RestMethod 'https://api.github.com/repos/Vanilla-SilQ-HD/Routing/releases/latest'
$base = "https://github.com/Vanilla-SilQ-HD/Routing/releases/download/$($release.tag_name)"
Invoke-WebRequest "$base/blocked-domains.srs" -OutFile blocked-domains.srs
Invoke-WebRequest "$base/blocked-domains.srs.sha256" -OutFile blocked-domains.srs.sha256
$expected = (Get-Content blocked-domains.srs.sha256).Split(' ')[0]
if ((Get-FileHash blocked-domains.srs -Algorithm SHA256).Hash -ne $expected) { throw 'SHA-256 mismatch' }
```

Для фиксации или отката используйте URL конкретного тега: `releases/download/<tag>/blocked-domains.srs`. Автоматика не перезаписывает и не удаляет опубликованные релизы.

## Локальная сборка

Нужен Python 3.11+; CI использует Python 3.13. Установщик закреплённого компилятора поддерживает Windows и Linux x64. Версия sing-box и SHA-256 официальных архивов зафиксированы в [tools-lock.json](../config/tools-lock.json). Сейчас используется sing-box 1.14.4 и формат исходного rule-set v3. Пример подключения в README использует поля sing-box 1.14+; другие версии клиента нужно проверять отдельно.

Windows PowerShell, из корня репозитория:

```powershell
python -m venv .venv
& ./.venv/Scripts/python.exe -m pip install --require-hashes -r requirements.txt
& ./.venv/Scripts/python.exe -m unittest discover -s tests -v
& ./.venv/Scripts/python.exe scripts/install_tools.py
& ./.venv/Scripts/python.exe scripts/build.py --output dist/first
```

Linux:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements.txt
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python scripts/install_tools.py
.venv/bin/python scripts/build.py --output dist/first
```

Повторная проверка из кеша без скачивания источников:

```powershell
& ./.venv/Scripts/python.exe scripts/build.py --offline --previous dist/first/manifest.json --output dist/replay
```

Каталог результата должен быть новым или пустым. Сборщик компилирует набор, декодирует его обратно, сравнивает все доменные условия и выполняет `sing-box check`. Сетевой сервис не запускается. Готовый каталог появляется только после проверок; неудачная сборка не перезаписывает предыдущий результат. Локальные сборки автоматически не публикуются.

## GitHub Actions и собственный форк

Основная ветка workflow — `main`. В форке включите Actions и запустите **Build selective VPN domain list → Run workflow**. Первому релизу не требуется предыдущая база сравнения. Публикация использует `GITHUB_REPOSITORY`, поэтому файлы попадут в Releases форка; ссылки в его README нужно заменить на свои.

Расписание: `35 0,6,12,18 * * *` UTC. Запуск также доступен вручную и при изменениях сборщика, его настроек или тестов. Изменение только README не вызывает пересборку. GitHub может задерживать расписание и [отключать его в публичном репозитории после 60 дней без активности](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule); при остановке обновлений проверьте состояние workflow.

Сборочный job имеет права чтения. Отдельный job публикации получает `contents: write` только после его успеха. Используется встроенный `GITHUB_TOKEN`; личный токен не нужен. При политике организации, запрещающей запись, потребуется изменить разрешения Actions в настройках репозитория.

Публикация сначала создаёт черновик `rules-<run_id>-<attempt>`, загружает все вложения и проверяет их обратным скачиванием. Только затем релиз становится публичным и назначается Latest. Неуспешный черновик может остаться для диагностики. При одинаковом `.srs` и рецепте сборки новый релиз не создаётся, а текущий бинарный файл повторно проверяется.

Артефакт `selective-vpn-rules` содержит полный результат и снимки источников; срок хранения — 2 дня. `rules-manifest` хранится 90 дней и служит базой сравнения следующего успешного запуска. Свежие отчёты сборок доступны в артефактах, даже если релиз не изменился.

## Если сборка остановилась

Ошибка обязательного источника, неожиданная структура данных или повреждённый файл останавливают публикацию. Частичный набор не выпускается. Падение числа условий более чем на 20%, рост более чем на 50%, смена состава источников или база сравнения старше 7 дней требуют проверки. Пороговые значения находятся в [policy.json](../config/policy.json).

Сначала посмотрите причину в Actions и сравните источники с последним manifest. Если изменение намеренное и проверено, запустите workflow вручную с `reset_baseline=true`. Он сформирует новую базу сравнения; известное предупреждение об отсутствии предыдущей базы допускается только для первого релиза или такого явного ручного сброса. Остальные предупреждения по-прежнему блокируют публикацию.

Пока сборка не исправлена, постоянная ссылка отдаёт последний успешный релиз. Его доступность не означает, что данные продолжают обновляться.
