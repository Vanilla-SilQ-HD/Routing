# Руководство пользователя

Проект публикует наборы для выборочной маршрутизации: заблокированные и недоступные ресурсы направляются через VPN, всё остальное — напрямую. Наборы одинаковы для любого роутера или компьютера с sing-box 1.14+; привязки к конкретной модели оборудования нет.

## Источники данных

Проект объединяет **13 источников** для покрытия заблокированных и недоступных в России ресурсов:

- **Основные блок-листы**: Antifilter, Re-filter, itdog, RKN, unavailable-in-russia
- **Агрегатор**: amatol/awgmanager-lists
- **Специализированные сервисы**: Google AI, Telegram, Bungie, Kinopub, Gemini, TikTok

Общие категории вроде «все соцсети» или «все СМИ» не используются: они содержат доступные в России ресурсы и нарушают принцип «остальной трафик — напрямую».

Полный список с описаниями см. в [README](../README.md#источники-доменов).

## Вариант 1. AWG Manager

1. Создайте и проверьте VPN-подключение. Его имя может быть любым.
2. Откройте [Catalog](https://github.com/Vanilla-SilQ-HD/Routing/releases/latest/download/catalog.json) и примените профиль **Full** или **Compact**.
3. Если используете `presets.user.json`, сохраните его в каталог данных AWG Manager. Существующий файл не перезаписывайте: объедините массив `presets` вручную.
4. Отдельно добавьте Remote Rule Set `routing-direct-exceptions`:
   - Source: `https://github.com/Vanilla-SilQ-HD/Routing/releases/latest/download/routing-direct-exceptions.srs`
   - Type: `Remote`; Format: `Binary`; Update interval: `6h`.
5. Настройте порядок правил:

| Порядок | Набор | Outbound |
|---|---|---|
| 1 | Локальные и системные правила | Как требует ваша конфигурация |
| 2 | `routing-direct-exceptions` | Direct |
| 3 | `routing`, `routing-services`, `routing-registry-ip` | Ваш VPN |
| 4 | Всё остальное | Direct |

Compact отличается только уменьшенной доменной базой; сервисные сети и точные registry-IP в него также входят. `routing-registry-ip-cidr` подключается отдельно и необязателен.

Для обновления наборов через Direct включите кеш. Если GitHub недоступен напрямую, выберите VPN для скачивания и проверьте холодный старт.

## Вариант 2. sing-box

В `route.rule_set` добавьте удалённые наборы с `format: binary` и `update_interval: 6h`. В `route.rules` Direct-исключения должны стоять выше VPN-наборов, а `route.final` должен быть `direct`. Готовый фрагмент находится в [README](../README.md#готовый-json-для-sing-box).

Имена `vpn` и `direct` в примере условные: замените их на свои outbound. Не копируйте настройки DNS или inbound чужого роутера.

## DNS

- Для VPN DNS используйте только доменный набор `routing` или `routing-core`.
- IP-наборы в DNS-правила не добавляйте.
- Доменные Direct-исключения направляйте в прямой DNS выше VPN-правила.
- При FakeIP клиенты должны использовать FakeIP DNS роутера; собственный DoH/DoT клиента может обойти его.

## Проверка

Откройте несколько заблокированных и обычных ресурсов и проверьте журнал соединений:

- ресурс из VPN-набора использует ваш VPN-outbound;
- обычные сайты используют Direct;
- Direct-исключение не попадает в VPN;
- IPv4 и IPv6 проверяются отдельно.

[Dashboard](https://vanilla-silq-hd.github.io/Routing/) показывает источники и хеши каждого набора. Для проверки файла скачайте соответствующий `.srs.sha256` или общий `SHA256SUMS` из [последнего релиза](https://github.com/Vanilla-SilQ-HD/Routing/releases/latest).

## Собственные правила

Примеры находятся в [`config/example-config/`](../config/example-config/README.md) и не применяются автоматически. Для каждого правила нужны `kind`, `domain`, `reason`; для Direct-исключения также `review_after`.

В `manual-vpn.json` разрешены только `domain` и `domain_suffix`. Точный публичный IP можно добавлять только в Direct-исключения. Не добавляйте целые общие зоны, CDN или непроверенные диапазоны.

## Ограничения

Полного списка всех блокировок не существует. Доступность зависит от провайдера и времени; P2P-адреса, динамические голосовые серверы, ECH и клиентский DoH/DoT не покрываются полностью статическими наборами. Мониторинг является диагностикой и не меняет маршруты автоматически.

## Часто задаваемые вопросы (FAQ)

### Какой профиль выбрать: Full или Compact?

- **Full** — максимальное покрытие, включает все 13 источников. Рекомендуется для большинства пользователей.
- **Compact** — без двух крупнейших реестров (Antifilter full и RKN). Подходит для устройств с ограниченной памятью.

### Как часто обновляются наборы?

Наборы обновляются **4 раза в сутки**: 03:35, 09:35, 15:35 и 21:35 по Москве. При изменении источников создаётся новый релиз.

### Что делать, если ресурс не открывается?

1. Проверьте, что ресурс есть в наборе через [Dashboard](https://vanilla-silq-hd.github.io/Routing/)
2. Убедитесь, что правила применяются в правильном порядке (Direct-исключения выше VPN)
3. Проверьте DNS-настройки
4. Если ресурс отсутствует — откройте issue «Ресурс идёт не по тому маршруту»

### Можно ли добавить собственные правила?

Да, создайте форк репозитория и добавьте правила в `config/manual-vpn.json` или `config/direct-exceptions.json`. Примеры в `config/example-config/`.

### Почему IP-адреса добавляются консервативно?

Один IP может обслуживать множество сайтов. Автоматическое добавление всех IP заблокированных доменов привело бы к маршрутизации через VPN легитимных ресурсов на shared hosting/CDN.

## Troubleshooting

### Наборы не обновляются

- Проверьте доступность GitHub у вашего провайдера
- Если GitHub заблокирован, настройте скачивание через VPN (`Download detour: ваш VPN`)
- Включите кеш в настройках AWG Manager

### Высокое потребление памяти

- Используйте профиль **Compact** вместо Full
- Отключите необязательный набор `routing-registry-ip-cidr`
- Измерьте реальное потребление: `scripts/measure_memory.py`

### Ресурс идёт не по тому маршруту

1. Проверьте порядок правил: Direct-исключения должны быть **выше** VPN-правил
2. Убедитесь, что ресурс не попадает под широкие CIDR (если включены)
3. Добавьте Direct-исключение в `config/direct-exceptions.json` вашего форка

Если маршрут неверен, откройте issue «Ресурс идёт не по тому маршруту» и укажите домен/IP, ожидаемый и фактический маршрут, сработавшее правило и версию набора.
