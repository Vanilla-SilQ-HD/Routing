# Сети приложений: источники и охват

[← README](../README.md)

`blocked-services-ip.srs` дополняет доменный набор для соединений, в которых роутер не получает имя назначения. Сейчас в него входят сети Telegram. Это расширяемый набор проверенных сервисных источников; он не обещает распознавать любой трафик всех приложений.

## Почему нельзя просто получить IP всех доменов

Домен и IP не имеют однозначного соответствия. На одном адресе CDN могут работать заблокированный сайт и множество доступных сервисов. DNS-ответы меняются по времени и региону, а доменный суффикс охватывает поддомены, которые нельзя перечислить одним DNS-запросом. Приложение также может получать адрес сервера внутри собственного протокола, без DNS.

Массовое разрешение доменного списка в IP изменило бы правило: вместо конкретного сайта в VPN попадали бы все соединения к его общему адресу. Поэтому домены остаются доменами, а IP добавляются из отдельно выбранных источников. В конфиге оба набора направляются в VPN, по умолчанию используется Direct, личные исключения размещаются выше. Для выбора DNS-сервера используется только доменный набор.

## Telegram

Обязательные источники:

- [Официальный CIDR-список Telegram](https://core.telegram.org/resources/cidr.txt): IPv4 и IPv6.
- [RIPE RIS / RIPEstat](https://stat.ripe.net/docs/data-api/api-endpoints/ris-prefixes): сети с `AS44907`, `AS59930`, `AS62014`, `AS62041`, `AS211157` как источниками BGP-маршрута. Транзитные сети не включаются. Идентичность оператора проверяется отдельным ответом [AS Overview](https://stat.ripe.net/docs/data-api/api-endpoints/as-overview).

На **6 ноября 2026 года** объединение этих AS добавляет к официальному списку `95.161.64.0/20`. [RIPE RIS](https://stat.ripe.net/data/ris-prefixes/data.json?resource=AS62041&list_prefixes=true&types=o) видит его анонс от `AS62041`; [маршрутный объект RIPE](https://rest.db.ripe.net/search.json?query-string=95.161.64.0%2F20&type-filter=route) указывает `TM Subnets` и `AS62041`. [RDAP](https://rdap.db.ripe.net/ip/95.161.64.0) содержит имя сети `TM-SUBNETS` и контакт Telegram Messenger Inc, а регистрантом указывает Global Network Management Inc. Это подтверждение использования диапазона Telegram, а не утверждение о владении адресами.

Сборка проверяет имя оператора и номер AS, свежесть снимка, структуру ответа и границы сетей. Снимки и хеши сохраняются. Это помогает учитывать новые анонсы выбранных AS без ручного добавления адресов; смена оператора или неожиданное расширение требует проверки.

У Discord [голосовой протокол](https://docs.discord.com/developers/topics/voice-connections) передаёт адрес сервера внутри соединения, а значительная часть голосовой инфраструктуры [работает на Cloudflare](https://discord.com/blog/how-we-moved-discord-voice-to-the-edge). Списки исходящих IP вебхуков или поисковых роботов не являются списками адресов, к которым подключается пользовательское приложение.

## Пределы покрытия

Даже сервисные сети не покрывают произвольные адреса собеседников в [P2P-звонках Telegram](https://core.telegram.org/api/calls), сторонние прокси и новые серверы вне выбранных источников. Списки не проверяют доступность каждого ресурса у конкретного провайдера. Новые источники можно добавлять после проверки назначения, общих сетей и поведения обновлений; широкое правило для всего облака такой проверкой не заменяется.
